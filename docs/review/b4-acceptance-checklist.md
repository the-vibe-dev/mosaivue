## Top remaining product gaps

PTZ and preset controls are outside this b4 candidate. No PTZ camera is available at the test site, so hardware compatibility is explicitly **untested**. Keep PTZ unimplemented/unsupported in release notes until the feature exists and a vendor-camera acceptance case passes.

1. **Full-layout asynchronous acceptance:** synchronous rollback does not prove every new branch produces frames. Manual rotation readiness now covers a narrower operation.
2. **Physical output management:** true multiple monitors, portrait rotation, connector selection, refresh-mode control, and blanking control remain unimplemented. Feature flags describe these limitations; they are not implementations.
3. **Operation progress and cancellation:** some backend work still blocks the event loop, and cancelling an await cannot stop an already running worker thread. A serialized command/operation model with explicit ownership remains future work.
4. **Presentation and control coverage:** audio output, native pixel sizing, per-tile borders/backgrounds, renderer snapshots, and OMX labels/manual crop remain absent. Complete placeholder failure policy and synchronized rotation groups also remain gaps.
5. **Stronger liveness and history:** OMX Playing confirmation does not prove new video frames. Durable per-camera health history, uptime/recovery metrics, and useful alert delivery would improve operation and diagnosis.
6. **Schedule management:** per-schedule timezone, bounded manual overrides, and explicit end-of-window fallback are not implemented. Equal start/end means one local calendar-day window, which may span 23 or 25 elapsed hours at daylight-saving changes.
